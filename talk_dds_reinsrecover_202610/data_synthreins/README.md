# Synthetic reinsurance dataset for the talk (`data_synthreins`)

A reproducible alternative to `../demo_business/`, generated by the private
`construct_synthetic_reinsurance_data` generator (Phase 1 + Phase 2). Nothing in
`demo_business/` or the talk `.qmd` has been changed; the table names and leading
columns mirror `demo_business` so the data can be swapped in later.

## Generator command

Generator commit: `2bff93775a9293d71cdf9cfb96ecafbdc186b35b`
(`git -C construct_synthetic_reinsurance_data rev-parse HEAD`). No host R, so it was run in
`docker.io/rocker/tidyverse:4.5.1` (the generator's own base image) with the repo mounted read-only:

```sh
Rscript scripts/generate.R --seed=5 --tier=large --phase=2 --periods=8 --format=csv --out=<dir>
# equivalent: just podman-generate --seed=5 --tier=large --phase=2 --periods=8 --format=csv --out=<dir>
```

Re-run twice into separate directories: both were byte-identical (`diff -r`) to
`raw/phase2_large_seed5/`. The talk-ready tables are rebuilt from the raw csv with:

```sh
# from talk_dds_reinsrecover_202610/ (image built once with `just podman-build`)
podman run --rm --userns=keep-id \
  -v <data_workshops>:/home/rstudio/reinsrecover:z -v <generator>/examples/mega:/mega:ro \
  kaybenleroll/dds-talk-reinsrecover:latest \
  Rscript /home/rstudio/reinsrecover/talk_dds_reinsrecover_202610/data_synthreins/derive.R \
  /home/rstudio/reinsrecover/talk_dds_reinsrecover_202610/data_synthreins /mega/csv
```

Run in the talk image (`localhost/kaybenleroll/dds-talk-reinsrecover:latest`, built from the unmodified `Dockerfile`; arrow comes
with the rocker base, igraph/ggraph/tidygraph from the Dockerfile): every derived output, including the parquet files, was
byte-identical (md5) to the committed ones. Deterministic.

**Why seed 5 won.** It is the only shortlisted run with the full mix the talk teaches: proportional
(QS and surplus) in front of XoL towers up to 7 layers deep, a clash, aggregate and stop-loss covers,
reinstatements, a 7-node longest path, nine convergence nodes and 36 cross-scope edges, plus multi-LOB

actually pays (they are touched, with `ceded = 0`), and no event shows a proportional-XoL-proportional
"sandwich" ordering (no proportional treaty ranks above an XoL that pays). (3) The talk's `EV02`-style
"mega-cat through clash into aggregate/ILW" story would need a different seed or more periods; stopping rule
applied, so not pursued.

## Derivation rules (`derive.R`)

- **`treaty_id`**: short ids by type prefix (`QS GQS SUR XR XO CLASH AGG SL ILW`), numbered by
  (chain_rank, generator id) within type; tower layers get `_L<k>`. The generator id is kept as
  `generator_treaty_id`. Surplus keeps the generator value `surplus` (the demo used `surplus_share`).
- **`treaty_label`**: proportional `"<scope name> <QS|Surplus|Group QS> <cession %>"`; XoL layer
  `"<scope name> <type> <limit>XS<attachment> L<layer>"` (millions); single clash/stop-loss/agg similar
  without `L`; ILW `"<scope name> ILW <limit>"`. Scope name is the LOB name with the `(P001 x.y)` suffix
  removed, the segment name, or `Group`.
- **`description`**: deterministic sentence from type/scope/layer/limit/attachment/reinstatements.
- `need_id` is `NA` (kept for column parity). Extra columns follow the demo's 13: `generator_treaty_id`,
  `scope_type`, `scope_name`, `tower_id`, `n_layers`, `premium_linked_limit`, `industry_trigger`.
  `scope` is the declared scope id (footprints in `raw/.../coverage_df.csv` can be wider).
- **`inuring_edges` / `edges_tbl`**: `edge_type` uses the demo vocabulary: `converge` if the target has
  more than one parent, else `chain`. The generator's own `adjacent|skip` is kept as `edge_kind`
  (plus `rank_gap`). **Decision for the user:** swap which of the two should feed `edge_type`.
- **`nodes_tbl`** is the connected subset of `treaties.csv` (51); `treaties.csv` has all 59.
- **`loss_events.csv`**: six illustrative events chosen deterministically by scenario (simple attritional,
  most layers exhausted, first event pushing a treaty-period past 1x limit, largest multi-LOB cat,
  convergence, largest total recovery). `entry_treaty` = lowest `chain_rank` treaty with a row for
  the event in `flow_df`. `gross_loss` = sum over the event's LOB cells. `generator_event_id` and
  `scenario` are extra.
- **`loss_allocation_walkthrough.csv`**: per event x treaty, summed over LOB cells. `gross_in` =
  `subject_loss_in`, `ceded` = `ceded`, `net_out` = `gross_in - ceded` (equals `retained_after`),
  `layer_exhausted` = non-proportional treaty with `ceded >= limit * (1 - 1e-9)`,
  `final_net_retained` = event gross minus total indemnity ceded (ILW is excluded as non-indemnity).
  Values come from the functional recompute below (it reconciled; `walkthrough_functional.csv` was
  therefore not needed).

## How the generator computes `flow_df` (read from `lib/lib_flows.R`)

- **Does not use `edges_df`.** The walk is a global order by `(chain_rank, treaty_id)`; a tower is one slot at
  its layer-1 rank. The inuring DAG is descriptive; flows never read it. A "skip" edge has no effect.
  `lib_inuring.R` builds the edges only.
- **State**: one mutable residual per cell `(event, lob, loss_type)`, starting at `gross_loss`; each treaty in
  rank order reads and reduces it, so a lower-rank treaty's cession shrinks what later treaties see
  (multi-parent convergence is therefore implicit: a cell passes through every treaty that covers it).
- **Proportional** (`quota_share`, `group_quota_share`, `surplus`): per cell, `cession_pct x residual`, cell by
  cell in `lob_id` order; the premium-linked cap (QS with `premium_linked_limit`) limits cumulative cession
  per period to `limit`.
- **Footprint XoL** (`xol_per_risk` on `large` events; `xol_per_occurrence`, `clash` on `cat` events): sum the
  residual `R` over the treaty's coverage LOBs for the event; every layer of a tower applies its own
  attachment and limit to the same `R` (layers do not erode each other), recovery
  `min(max(R - attach, 0), limit)`, capped by the remaining `(reinstatements + 1) x limit` for that
  treaty-period; the recovery is written back to the cells pro-rata to their residual.
- **Annual** (`aggregate_xl`, `stop_loss`): once per period on the whole-period residual of the declared
  scope after earlier treaties, same pro-rata write-back; no event-level trigger.
- **ILW**: non-indemnity; pays `limit` if the event's `industry_loss >= industry_trigger`; never touches
  the ledger; emitted for every cat event including ones with no `loss_df` rows.
- **Reinstatements**: `reinstatement_consumed` per row is `ceded / limit` (not cumulative). Cumulative use
  per treaty and period lives in a hashed environment, reset by key each period (no carry-over between
  periods), reported as `treaty_period_df.reinstatements_used = cum ceded / limit`; reinstatement premium
  `= rol x net_subject_premium x max(0, used - 1)`. Events are processed in `(event_seq, event_id)` order.
- **Style: imperative.** Hashed environments mutated in place, nested `for` loops, growing a list of row
  chunks; helpers are vectorised per event but not pure. Not a fold. Unclear to me: the exact meaning
  of `premium_linked_limit` for QS (only its enforcement was read), and why xol_per_risk only responds to
  `large` events (a design choice in the docs, not verified here).

## Independent functional recompute

`derive.R` re-implements the above as pure functions: one per-treaty-unit `step_*` function returns a new
state `(ledger, cap usage, emitted rows)`, folded with `Reduce` over the units in topological
(rank) order and over events/cells inside each unit. No in-place mutation of shared state. The talk `.qmd` has no
allocation code (it only reads the csv), but its slides use the same convention: pro-rata allocation of a
treaty recovery back to segments, and, in the demo walkthrough, all layers of a tower showing the same
`gross_in`, which matches the generator.

Reconciliation against `flow_df` (`recompute_reconciliation.csv`):
2736 of 2736 rows match (rate 1.0), none present on one side only; max abs difference 3.7e-9 in
`ceded` and 7.5e-9 in `subject_loss_in` (csv rounding at 15 significant digits on values near 1e8),
tolerance 1e-9 relative. `reinstatements_used` matches `treaty_period_df` on all 272 treaty-periods
(max diff 4e-16). One discrepancy found while building it, fixed in the recompute (not tuned): ILW rows
exist for cat events with no `loss_df` rows; the recompute now emits ILW from `event_df`.

## Caveats

- Labels, descriptions, short ids and event descriptions are synthetic and rule-built; LOB/segment names come
  from the generator catalogue. Nothing here is from a real programme.
- Rate-on-line, attachments and limits are structurally derived (sized off synthetic premium and expected loss),
  not actuarial; "surplus" is a flat `cession_pct` in flows.
- In the walkthrough `gross_in` of a treaty is its own footprint's residual, so `net_out` of one row is not
  the next row's `gross_in` (towers read the same pre-tower `R`; multi-LOB events differ by footprint).
- `flow_df` ignores the inuring edges; the DAG and the loss walk agree only through `chain_rank`.
- The 8-period run does not exercise clash/aggregate/stop-loss payouts or a sandwich ordering.
